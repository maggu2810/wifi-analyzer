# Internationalization (i18n)

## Two kinds of text

| Kind | Examples | Lives in | Mechanism |
|---|---|---|---|
| **Domain text** | field labels ("Group Cipher"), enum names ("CCMP-128" stays, "reserved", "Personal"), summary labels ("WPA2/WPA3-Personal (transition)"), diagnostics ("length 3 is below minimum 4") | `libs/wifi-analyze/i18n/` | gettext `.po` catalogs compiled into C++ tables |
| **App chrome** | buttons, menus, settings, onboarding, CLI help | each frontend | Android `res/values*/strings.xml`; CLI: English only for now; Qt later `.ts` |

Domain text belongs to the library because it is generated by the library (thousands of
field names across all elements) and must read the same in every frontend. Duplicating
it in `strings.xml` would scatter it and break every time a decoder is added.

## Library design

- Every user-visible domain string has a stable **message key** (`rsn.group_cipher`,
  `akm.sae`, `diag.length_below_min`) and an English source text.
- Source of truth: `libs/wifi-analyze/i18n/messages.pot` (extracted/maintained by
  `tools/gen_i18n_catalog.py` from a key table), translations in `de.po`, … – standard
  format, editable with Poedit/Weblate/any tool.
- At build time the tool compiles catalogs into `constexpr` sorted tables
  (`src/generated/catalog_<lang>.inc`). No runtime gettext/ICU dependency → works with NDK
  and embedded toolchains.
- Diagnostics carry arguments; messages use positional placeholders (`{0}`, `{1}`).
  Plural forms only where really needed (simple `one`/`other` per catalog).
- Technical identifiers are **not** translated: cipher/AKM suite names (CCMP-128, SAE),
  standard names (802.11ax), units.
- API: `localizer("de")` → falls back per message to English; `available_locales()`.

## Flow to the frontends

- **JSON** (CLI `--format json`, JNI): contains both the stable `key`s and the `label`s
  rendered in the requested locale, so consumers can either display directly or map keys.
- **CLI:** locale from `--lang` or `LC_ALL`/`LC_MESSAGES`/`LANG`, default English. CLI's own
  messages (usage, errors) stay English in v1.
- **Android:** passes the app's current locale (per-app language setting supported) on each
  decode call; re-decodes (cheap) when the locale changes.

## Languages

v1: English. Planned next: German. Adding a language = adding a `.po` file, no code change.
